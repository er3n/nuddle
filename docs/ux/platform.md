# Android platform notes

Min SDK 26, target the current SDK (35+). The app is declared to Play as an alarm app. If accepted, setup shrinks to the notification dialog; if not, the fallback flow below runs. The code is the same in both cases: each setup step checks its permission first and is skipped when already granted.

## Permissions

| Permission | Manifest | How it is requested | Without it |
|---|---|---|---|
| Notifications | `POST_NOTIFICATIONS` | System dialog, setup step 1. Cannot be skipped. | App cannot work, step shown again |
| Exact alarms | `USE_EXACT_ALARM` (declared) + `SCHEDULE_EXACT_ALARM` | If `canScheduleExactAlarms()` is false, `ACTION_REQUEST_SCHEDULE_EXACT_ALARM`, setup step 2 | Approximate alarm with `setWindow`, reachability drops, warning in the bell |
| Full screen | `USE_FULL_SCREEN_INTENT` (declared) | If `canUseFullScreenIntent()` is false, `ACTION_MANAGE_APP_USE_FULL_SCREEN_INTENT`, setup step 3 | `FULL_SCREEN` degrades to `SOUND` |
| Camera | `CAMERA` | System dialog when the photo screen first opens | Photo step falls back to plain "Bitti" |
| Microphone | `RECORD_AUDIO` | On the first mic press | Text only |
| Boot | `RECEIVE_BOOT_COMPLETED` (also delivers `LOCKED_BOOT_COMPLETED`) | Automatic | Alarms lost on reboot |

- No contacts permission: the invitee is picked with `ActivityResultContracts.PickContact` (single contact).
- Battery optimization exemption (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, the one-tap system dialog) is setup step 4 only on phones whose manufacturer puts sleeping apps to sleep (Samsung, Xiaomi, Huawei, Oppo, Vivo and their sub-brands; `SetupRules.needsBatteryStep`). Stock Android keeps three steps: `setAlarmClock` is not deferred by Doze there. Decided 2026-10-15 after a Samsung put the app into deep sleep (open-questions #49, NUD-75).
- Play policy for `USE_EXACT_ALARM` and `USE_FULL_SCREEN_INTENT` is still to be confirmed; submit the first closed test build early.

## Alarms and pokes

- The server pushes plan steps with a high priority FCM data message. The device writes them to Room and calls `AlarmManager.setAlarmClock()` per step.
- On `BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`, `TIME_SET` and `TIMEZONE_CHANGED`, all pending alarms are re-set from Room.
- **Direct boot (NUD-125).** After a reboot, before the first unlock, Room and the app's other files cannot be read. So every time the alarms change, the app also writes the pokes it has armed to device-protected storage: per step only the task id, plan version, seq, planned time, level and whether it is an `at` task, plus the quiet hours. No title, detail, name or phone number. On `LOCKED_BOOT_COMPLETED` the boot receiver (direct boot aware, like the alarm receiver) sets those alarms again. A poke that comes due before the first unlock still rings: quiet hours are checked as usual, and the notification says only that there is a poke ("Bir dürtmen var", "Kilidi açınca görürsün") with no buttons, since the task itself cannot be read yet. `FULL_SCREEN` rings as `SOUND` then, because the full screen poke needs the task. The alarm volume is not raised then either: the person's own level is kept with the app's other preferences, which cannot be read yet. After the unlock (`BOOT_COMPLETED`) the app takes over what rang: the step is marked fired, its fired report goes out with the time it really rang, and a poke still up is shown again in full with its buttons. That holds for a snoozed ring too, whose step already rang before the reboot (NUD-160). Signing out empties this store too.
- **Hourly check (NUD-125).** While at least one poke has an alarm, a periodic WorkManager job (about every hour) compares the alarms the phone should have (the same rule as a re-arm) with the ones that are really set, and sets the missing ones again. A phone that dropped alarms (an OEM battery saver, a killed process) is noticed before the next step, not only on the next launch. A re-install is reported as a non-fatal in the crash report (ADR 0023, opaque ids and counts only). A step that came due since the last check without an alarm and would have rung counts as lost on this phone (Missed-ring detection below). With no poke left to arm the job stops itself.
- **Early wake on some OEMs: deferred.** Some phones (Honor, Google, Xiaomi on API 28-33) are known to deliver an exact alarm a few seconds late; ringing 5-30 s early with a short wakelock is not done until the phone tests show late rings.
- **Already done? (NUD-129).** The quiet "Zaten yaptın mı?" before a loud step (domain.md, Already done?) needs to know that the person is using the phone. `ACTION_USER_PRESENT` (the unlock) has not reached manifest receivers since Android 8, and a receiver registered at runtime hears it only while the app's process lives, and on Android 14+ late while the process is cached. So the phone does both: while a loud step is armed the app registers the unlock receiver at runtime (from the armed set and on every process start), and it keeps one check alarm (`setAndAllowWhileIdle`, inexact, no alarm icon, no exact alarm permission) every 2 minutes from 10 minutes before each loud step until 1 minute before it. When the check fires and the screen is on and not locked (`PowerManager.isInteractive`, `KeyguardManager.isKeyguardLocked`), the rule runs; in Doze the check waits for the screen to come on, which is the moment that counts. The notification goes to `poke_silent` with its own id and group, Bitti only, and times out when the step is due; the step's poke replaces it. Its "shown" mark per task and plan version is kept in the session DataStore.
- On fire, a `BroadcastReceiver` re-checks quiet hours and plan version, then shows the notification for the level. For `FULL_SCREEN` the notification opens `PokeActivity` via `setFullScreenIntent` (`showWhenLocked`, `turnScreenOn`).
- Bitti, Ertele and Bugün olmaz apply locally first (remaining alarms cancelled), then go to the server via the WorkManager outbox. Poking stops immediately even offline. Once started, the local close and the outbox write finish together, also when the screen that started them (the task detail going home after İptal et) closes at once (NUD-143).
- A task that closes elsewhere (the sender cancels, it is missed, the connection is removed) loses its alarms and its poke at the next sync: a poke notification that is up goes, and an open full screen poke closes. A snoozed ring survives a sync until the server's shifted plan replaces it (NUD-64).
- Quiet hours are checked when the server plans and again on the device before ringing.
- **Alarm volume (NUD-68).** A poke rings on the alarm stream, whose level the person sets apart from the ringer, and a low one made pokes nearly silent in the phone test. When a `SOUND` or `FULL_SCREEN` poke rings and the alarm stream is below 70% of its range, the app raises it to 70% and keeps the person's level; once no poke notification is left (answered here, closed by sync, or swiped away and the app opened) it puts that level back. A phone that refuses the change (some do in Do Not Disturb) rings at the person's own level. A gradual rise like an alarm clock needs the app to play the sound itself instead of the channel, which is not done yet.
- **Task read aloud (NUD-124).** While a `SOUND` or `FULL_SCREEN` poke rings, the app says the task with Android `TextToSpeech` (pattern in `glossary.md`, Spoken poke) on the alarm stream (`USAGE_ALARM`, so it follows the raised alarm volume above), asking for transient audio focus that may duck the tone while it speaks. The first time about 3 seconds after the ring starts, then 2 more times 10 seconds apart, only while the poke notification is up; the tone itself stays the channel's and keeps ringing. During a phone call or a voice chat (audio mode in call or in communication, or the focus refused) that round says nothing, so the task is never spoken over a call; the tone rings as the system allows during a call (NUD-151). The engine must report a Turkish voice (`isLanguageAvailable(tr-TR)`); otherwise, or when the engine does not start, nothing is spoken and the tone rings as before. The voice runs in the app process: when Android freezes a cached app process, the voice may stop early while the tone goes on. Never in the locked direct boot notification (NUD-125), which has no task text. On for everyone in the MVP (open-questions #56). Package visibility needs the `android.intent.action.TTS_SERVICE` query in the manifest.

## Notification channels

| Channel id | Name (user visible) | Importance | Sound |
|---|---|---|---|
| `poke_silent` | Sessiz dürtmeler | DEFAULT | none (also "Zaten yaptın mı?", NUD-129) |
| `poke_alarm` | Dürtme alarmları | HIGH | alarm sound, `USAGE_ALARM` (pierces DND by default) |
| `tasks` | Görevler ve onaylar | DEFAULT | default (4b, the photo note, and the close notes of 4j) |
| `reach_out` | Ulaşılamayan kişi haberleri | HIGH | default |
| `system` | İzin ve kurulum uyarıları | LOW | none |
| `news` | Nuddle'dan haberler | DEFAULT | default |

A channel disabled in system settings is treated like a missing permission: reachability drops and the bell shows a warning. `news` is the exception (ADR 0025): turning it off only stops announcement notifications, the bell still lists them.

## Missed-ring detection

- Every fired alarm reports planned and actual time.
- The server counts a poke as lost when the report does not arrive while the device appears online.
- On launch, `ActivityManager.getHistoricalProcessExitReasons()` (API 30+) tells whether the previous exit was a force stop.
- The hourly check (Alarms and pokes) finds pokes whose alarm the phone dropped without a force stop: the newest step that came due since the last check without an alarm, outside quiet hours, on an open task's current plan, is kept as lost, like after a force stop.
- On a loss, the bell shows "Son dürtmen çalmadı" (2g) and brand-specific steps (2h). Steps come from a server JSON keyed by `Build.MANUFACTURER` (`GET /api/v1/brand-fix`), so they change without an app update; any other phone gets a default step. First version covers Xiaomi, Samsung, Huawei, Oppo, Vivo (dontkillmyapp.com as reference).
- The person can also open 2h themselves from profile ("Dürtmem çalmadı", NUD-126), with no loss detected. 2h ends with "Dürtmelerimi yeniden kur", which re-installs every alarm of this phone from the stored plans (`AlarmRearmer.rearm`, the same path as after a reboot). Nothing is reported to the server: a self-reported miss does not count as a loss and does not change the bell.

## Other

- Phone sign-in: SMS Retriever API reads the code without any SMS permission. The code screen listens, fills the six digits and submits; a new code listens again. The SMS ends with the app hash (`SMS_RETRIEVER_HASH`), which matches only the Play App Signing certificate, so sideloaded builds fall back to the keyboard's code suggestion.
- WhatsApp sign-in code (ADR 0029): before asking for a code, when WhatsApp (or WhatsApp Business) is installed, the app sends Meta's OTP handshake (`whatsapp-otp-android-sdk`) and declares a receiver for `com.whatsapp.otp.OTP_RETRIEVED`. Zero-tap hands the code to the app, one-tap opens the app with it; either fills the six digits and submits like the SMS Retriever. The template lists `com.dokukoza.nuddle` with the Play App Signing hash (`FdXmcSJuarV`), `app.nuddle.debug` with the local debug key hash and, while testers run it, `app.nuddle`. Without WhatsApp, or when the handshake fails, the code still arrives in the chat with a copy button. Zero-tap arrives at an exported receiver, one-tap opens `MainActivity` (the same action on its intent filter); both are exported because WhatsApp sends them, so the app takes a code only when it carries the `request_id` of the app's last handshake (SDK 1.0 checks this id in place of the older PendingIntent check). Breadcrumbs say `whatsapp_otp` and what happened, never the code or the id (ADR 0023).
- Sign-out wipe (NUD-141): Çıkış yap (7h), Hesabımı sil (7i) and a refresh the server rejects (`/auth/refresh` answers 401, so the session is gone, as after NUD-139) all run one local wipe: alarms are cancelled and the direct boot copy emptied, pokes that are up close with their voice (an open full screen poke closes when its task leaves Room), the alarm volume goes back, then the other notifications, queued work, Room, unsent photos and the session DataStore with the device id and sync cursor go, and whatever screen is open gives way to the welcome screen. Offline (no answer from `/auth/refresh`) the session stays and the call is retried later.
- Photo: opening the camera for a task (Bitti on a photo task's poke, 3a or 3b) takes that task's poke away with its sound and voice, like Ara on the full screen poke: the task stays open and the next steps ring as planned until the photo is sent (NUD-153). CameraX in the app (back or front lens, "Kamerayı çevir"), or the system photo picker (`PickVisualMedia`, no storage permission) for "Galeriden seç" (open-questions #48). Upload to a Supabase Storage signed URL through WorkManager with retries. (The handoff said R2; replaced by ADR 0002.)
- Voice: press and hold to record, release to send. Recognition runs on the phone (`SpeechRecognizer`, Turkish) and the transcript is written like typed text (open-questions #17, #40). `RECORD_AUDIO` is asked on the first hold.
- Share to Nuddle (NUD-127): `MainActivity` takes `ACTION_SEND` with `text/plain`, so Nuddle is in the system share sheet. `EXTRA_TEXT`, with `EXTRA_SUBJECT` on its own line above it when present and not already its start, is trimmed and cut to the 500 characters a write takes (`WriteTaskCommand`). Home puts it in the compose box (screens.md 2a); a share while another screen is open goes back to home first. Signed out, it waits like an invite link until sign-in reaches home (kept through a rotation, not through the process being killed). The breadcrumbs (ADR 0023) log "share", never the text. An `image/*` share (NUD-138) is taken too: the picture behind `EXTRA_STREAM`, read at once through the share's read grant into the same JPEG as a gallery pick, becomes the attached example photo (screens.md 2a), and `EXTRA_TEXT` goes in the box as above. Only one image; `ACTION_SEND_MULTIPLE` is not taken.
- Share: `Intent.ACTION_SEND` system sheet. Call: `ACTION_DIAL`. Message: `ACTION_SENDTO` with `smsto:` through the system chooser.

## Navigation

Single Activity with Navigation Compose, plus `PokeActivity` for the lock screen. Route groups and the canvas screens they cover are in `screens.md`.

- An existing user goes from the code screen straight to `home`. A new user without an invite goes from name to `home`; `setup` opens at their first task. An install that never ran setup also opens it from `home` as soon as someone is connected and a permission is missing: a reinstall (or the move from a sideloaded build to Play, which needs one) of someone who mostly receives tasks would otherwise never see it (NUD-103).
- Back never returns to sign-in steps. `home` is the root of the back stack.
- Error screens (6a to 6f) are states of their screen, not routes. The generic error (6f) is full screen only when nothing can be recovered.
- Deep links: invite links are `https://nuddle.app/i/{inviteCode}` (open-questions #13), verified App Links (`/.well-known/assetlinks.json` from the web app). Signed in, the link opens `consent/{inviteId}` for an open invite to me, otherwise the invalid invite screen 6d (open-questions #39). Signed out, the app asks for the invite preview (ADR 0016) and starts at the invited welcome (0b); the name screen (0e) is prefilled with the name the inviter typed. When the preview fails (invite no longer open, offline), the plain welcome (0a) shows. After sign-in the link opens the consent screen as above. Without the app, the link opens a page on the web. Notifications open `task/{id}`, `inbox` or `announcement/{id}`. An announcement's button opens an app route (`invite`, `profile`) or, for an `https://` target, the browser.

## Accessibility

- Every tappable element is at least 44 x 44 dp. Visually small ones (links, chevrons) use `minimumInteractiveComponentSize`.
- Text contrast at least 4.5:1. Text on `accent` is always `ink`. `textMuted` only for decoration.
- TalkBack: icon buttons have content descriptions ("Bildirimler, 1 okunmamış", "Profil", "Basılı tutup konuş", "Geri"). A TaskRow reads as one element: "Gelirken ekmek al, Sibel, bu akşam, Kurulu". ToggleRow is `Role.Switch`, ChoiceChip is `Role.RadioButton` with selection state.
- Font scale up to 200%. Fixed-height boxes use `heightIn(min = ...)` so they grow.
- Animations 150-250 ms; with system animations off, toasts and sheets appear instantly. Poke rings stay static.
- With TalkBack on, the undo toast lasts 10 s and takes focus.
